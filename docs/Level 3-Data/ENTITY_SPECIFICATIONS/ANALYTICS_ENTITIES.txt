# ANALYTICS_ENTITIES.md

# Analytics Entity Specifications

## Purpose

The Analytics bounded context provides business intelligence, reporting, dashboards, KPIs, and AI-powered insights across the AdotKazi platform.

Rather than querying operational tables directly, Analytics is powered by immutable events and aggregated metrics.

This architecture provides:

* Better performance
* Historical accuracy
* Time-series analysis
* AI insights
* Scalable reporting

Analytics is read-heavy and optimized for business intelligence.

---

# Analytics Philosophy

Analytics must be:

* Event-driven
* Immutable
* Near real-time
* Tenant-aware
* Scalable
* Explainable
* AI-ready

Operational databases remain optimized for transactions.

Analytics databases remain optimized for reporting.

# AnalyticsEvent

## Purpose

Represents an immutable business event.

Every significant action across AdotKazi generates an analytics event.

Examples:

* User Registered
* Opportunity Published
* Application Submitted
* Interview Scheduled
* Candidate Hired
* Placement Started
* Certificate Issued

---

## Aggregate Root

Yes

---

## Owner

Platform

---

## Fields

| Field           | Type      |
| --------------- | --------- |
| id              | UUIDv7    |
| organization_id | UUID      |
| event_name      | String    |
| entity_type     | String    |
| entity_id       | UUID      |
| actor_user_id   | UUID      |
| occurred_at     | Timestamp |
| payload         | JSONB     |

---

## Business Rules

Analytics events are immutable.

Events are append-only.

Events must never be updated.

---

## Domain Events

Analytics events originate from every bounded context.

# Shared Analytics Standards

All analytics entities must:

* Enforce tenant isolation.
* Generate immutable records where appropriate.
* Use UTC timestamps.
* Support asynchronous processing.
* Respect feature flags.
* Support AI-generated insights.

# Performance Considerations

* Never query operational tables for dashboard rendering.
* Precompute expensive metrics.
* Cache frequently accessed dashboards.
* Partition analytics events by date where appropriate.
* Archive historical events according to retention policies.
* Process analytics asynchronously.

---

# Security

* Analytics data must respect tenant boundaries.
* Dashboard permissions follow role-based access control.
* Sensitive reports require explicit authorization.
* Exported reports may have expiration dates.
* Personally identifiable information should be minimized in aggregated analytics.
