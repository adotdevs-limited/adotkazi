# RECRUITMENT_ENTITIES.md

# Recruitment Entity Specifications

## Purpose

The Recruitment bounded context manages the complete talent acquisition lifecycle.

It provides the entities required to create opportunities, manage candidates, process applications, coordinate recruiters, conduct interviews, evaluate applicants, extend offers, and complete hiring.

This bounded context depends on the Platform bounded context for authentication, organizations, memberships, permissions, and tenant isolation.

# Opportunity

## Purpose

Represents any opportunity an organization offers.

Supported opportunity types include:

* Full-Time
* Part-Time
* Contract
* Internship (IPT)
* Graduate Programme
* Apprenticeship
* Volunteer

Opportunity is the primary aggregate root of the Recruitment bounded context.

---

## Aggregate Root

Yes

Organization

## Relationships

Belongs To:

* Organization
* Branch
* Department
* Hiring Team
* Pipeline

Has Many:

* Applications
* Skill Requirements
* Interviews
* Offers

---

## Business Rules

* Opportunities belong to one organization.
* Opportunities use exactly one pipeline.
* Organizations may duplicate opportunities.
* Closed opportunities cannot receive new applications.
* Archived opportunities remain searchable internally.
* Scheduled opportunities become visible automatically at the publish date.

---

## Domain Events

* OpportunityCreated
* OpportunityPublished
* OpportunityUpdated
* OpportunityPaused
* OpportunityClosed
* OpportunityArchived

# Shared Recruitment Standards

All recruitment entities must:

* Enforce tenant isolation.
* Support audit logging.
* Generate domain events.
* Support optimistic locking where applicable.
* Respect soft delete policies.
* Validate ownership through organization boundaries.
* Record timeline history for significant actions.

---

# Performance Considerations

* Index organization_id, opportunity_id, candidate_id, and application_id.
* Index status and current_stage_id for workflow queries.
* Use composite indexes for tenant + status and opportunity + status.
* Optimize recruiter dashboards with precomputed summaries where appropriate.
* Synchronize searchable entities with Meilisearch asynchronously.
