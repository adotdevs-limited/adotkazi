# PLATFORM_ENTITIES.md

# Platform Entity Specifications

## Purpose

The Platform bounded context contains the foundational entities required for every tenant, user, authentication, authorization, configuration, and feature within AdotKazi.

These entities form the backbone of the multi-tenant SaaS architecture.

Recruitment, Internship (IPT), AI, Communication, and Analytics modules all depend on this bounded context.

---

Platform

# Organization

## Purpose

Represents a company (tenant) using AdotKazi.

Organization is the root aggregate for all tenant-owned resources.

Every recruitment activity belongs to exactly one organization.

---

## Aggregate Root

Yes

---

## Ownership

Platform

---

## Fields

| Field            | Type      | Required |
| ---------------- | --------- | -------- |
| id               | UUIDv7    | Yes      |
| name             | String    | Yes      |
| legal_name       | String    | Optional |
| slug             | String    | Yes      |
| status           | Enum      | Yes      |
| industry         | String    | Optional |
| company_size     | Enum      | Optional |
| website          | URL       | Optional |
| email            | Email     | Optional |
| phone            | String    | Optional |
| timezone         | String    | Yes      |
| country          | String    | Yes      |
| logo_document_id | UUID      | Optional |
| created_at       | Timestamp | Yes      |
| updated_at       | Timestamp | Yes      |
| deleted_at       | Timestamp | Optional |

---

## Relationships

Has Many:

* Branches
* Departments
* Memberships
* Opportunities
* Pipelines
* Settings
* Integrations
* Feature Flags

Belongs To:

* Subscription (future)

---

## Constraints

* Slug must be unique.
* Organization name required.
* Soft deletion only.
* Tenant data must never migrate automatically.

---

## Business Rules

* Organization owns all tenant resources.
* Organization cannot access another tenant.
* Organization can be suspended.
* Suspended organizations become read-only.
* Archived organizations retain historical data.

---

## Domain Events

* OrganizationCreated
* OrganizationUpdated
* OrganizationSuspended
* OrganizationReactivated
* OrganizationArchived

---

## Security

Tenant boundary enforcement begins here.

Every child entity inherits organization ownership.

# Shared Lifecycle

Every platform entity follows:

Draft (where applicable)

↓

Created

↓

Active

↓

Updated

↓

Suspended (optional)

↓

Archived (optional)

↓

Soft Deleted

---

# Shared Standards

All entities must:

* Use UUIDv7 identifiers
* Include audit fields
* Support soft deletes where appropriate
* Enforce tenant isolation
* Generate audit events for critical actions
* Respect optimistic locking where concurrent edits are possible

---

# Performance Considerations

* Index organization_id on all tenant-owned entities.
* Index user_id on user-related entities.
* Use composite indexes for common query patterns.
* Cache organization settings and feature flags.
* Avoid N+1 queries through eager loading where appropriate.

---

# Future Expansion

The Platform context is designed to support future capabilities without breaking existing models, including:

* Subscription and billing
* Single Sign-On (SSO)
* SCIM provisioning
* Organization groups
* Marketplace integrations
* White-label deployments
* API keys and OAuth applications
* Advanced compliance and governance
* Cross-organization administration
* Multi-region deployments
